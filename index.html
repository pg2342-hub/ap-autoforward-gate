AP Auto-forward Gate

A tool for the end of week 2 of an Agave AP Automation onboarding at a general contractor. It reads an export of the AI's suggested invoice coding and AP's final coding, and answers two questions.

How it fits Agave's AP workflow

On an auto-forwarded job Agave still sends every invoice to the PM. AP writes each rule above as a plain-language auto-tagging rule in Agave and clears every tagged invoice before the daily sync. In this tool's output, AP REVIEW means AP touches the invoice before it reaches the ERP, and AUTO-FORWARD TO PM means it goes from PM approval to the daily sync with no AP touch.

It is built around how Agave's AP Automation is documented to work (AP draft check, PM approval, auto-forward set per project, auto-sync set per account), so a team can switch auto-forward on job by job while AP keeps daily sync and clears tagged invoices first. Agave already checks for duplicates on its own; the tool repeats that rule so the eval covers every reason an invoice reaches AP.

eval/ holds 30 hand-written invoices after a gate window, each labeled by hand with the route and tags it should get, covering every rule and its edge cases (exactly at the scheduled value, one cent unallocated, 14 versus 15 days for duplicates, tax on repair versus capital improvement jobs, invoices that hit several rules). The pass bar is 30 of 30 and zero unsafe auto-forwards.

The first run scored 27 of 30. All three misses were errors in the eval set, not the tool: two cases reused an amount from an earlier case for the same vendor, which the duplicate rule correctly caught, and one sat exactly on the 14-day boundary before I had decided whether day 14 counts; I settled on "within 14 days" including day 14 and moved the case. The cases were fixed and the run is now 30 of 30 with zero unsafe auto-forwards.

The labels are written by hand and kept apart from the code, but they follow the same rules the code implements, so the eval checks that the code does what the rules say, not that the rules are right.

Limits

  • Each invoice is coded to one line; split coding would compare each line.
  • Once a contract line is overbilled, later invoices on it are tagged too until AP clears the line. Overbilling compares the invoice net of tax with the line's scheduled value. It does not model retainage or change orders not yet in the ERP.
  • The tax rules are a screen, not tax advice: they decide which invoices a person looks at.

Run it yourself

Python 3.9 or newer, standard library only. --out also writes the full AP queue (see sample_report.md).

python gate.py
python gate.py --out report.md
python gate.py --threshold 0.95 --min-invoices 25
python eval/run_eval.py
python -m unittest discover -s tests
